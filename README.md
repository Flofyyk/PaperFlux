# PaperFlux Server

**Русский** · [English](README.en.md) · [Android-клиент](https://github.com/Flofyyk/PaperFluxAndroid) · [Развёртывание](docs/DEPLOYMENT.md)

PaperFlux — TCP-туннель с передачей данных через Yandex Docs. Клиент принимает трафик приложений, а сервер на VPS доставляет его до адресата и возвращает ответы по тому же каналу.

Проект основан на [OpenFlux](https://github.com/p1neappleXpress/OpenFlux). Этот репозиторий содержит сервер и общее транспортное ядро PaperFlux; Android-приложение находится в отдельном репозитории.

## Как это работает

```text
Приложения на Android
        ↕
VPN-интерфейс → обработка TCP
        ↕
Шифрование PFS2
        ↕
Yandex Docs — канал совместного редактирования
        ↕
Расшифрование на VPS
        ↕
TCP-узел PaperFlux → целевой сервер
```

**Приём трафика.** Android-клиент создаёт системный VPN-интерфейс. Пакеты из него обрабатываются локальным сетевым стеком и передаются в TCP-туннель. Для десктопного режима предусмотрен вход через SOCKS5.

**Передача через документ.** Клиент и VPS подключаются к одному документу Yandex Docs. Транспорт использует служебные сообщения курсора в канале совместного редактирования: данные упаковываются в батчи, шифруются и кодируются для передачи внутри сообщений Socket.IO поверх Engine.IO/WebSocket. Для этой передачи не требуется записывать содержимое пакетов в текст документа.

**Выход в интернет.** VPS извлекает данные из сообщений и передаёт TCP-потоки целевому серверу. Ответы проходят обратный путь до приложения. Доступны два серверных режима: `proxy` открывает обычные исходящие TCP-соединения и не требует root; `raw` сохраняет пакетный режим и требует системной настройки Linux.

## Защищённая сессия

Профиль связывает клиента и сервер общими параметрами: идентификатором, секретом и документом. PFS2 использует X25519 для обмена ключами и AES-256-GCM для шифрования сообщений. До подтверждения защищённой сессии пользовательские данные не принимаются.

Шифрование действует между клиентом и VPS. Дальнейшая защита соединения с сайтом зависит от протокола приложения, например HTTPS. Сервис документа может наблюдать время, размер и частоту сообщений. Подробности: [PFS2](docs/SECURITY_PFS2.md).

## Соединение и восстановление

Подключение проходит три этапа: авторизация документа, установление защищённой сессии и проверка DNS/TCP через выходной узел. Успешного подключения WebSocket недостаточно для подтверждения работы всего туннеля.

При обрыве транспорт повторно получает параметры документа и создаёт новую WebSocket-сессию с новым идентификатором участника. Обычные ошибки используют ограниченную возрастающую задержку со случайной добавкой. Явное закрытие сессии редактором (`4007/drop`) обрабатывается как ротация канала: предыдущая сессия закрывается, а новая создаётся после короткой паузы. Пакеты имеют ограниченный срок хранения в очереди: устаревшие данные не отправляются после длительного обрыва.

Профиль может содержать один или два документа. При двух документах новый TCP-поток закрепляется за одним готовым каналом, поэтому пакеты одного соединения не перемешиваются между документами. Если один канал временно недоступен, второй продолжает обслуживать туннель, а закрывшийся восстанавливается отдельно.

## Совместимость

Основной сценарий — PaperFlux Android и сервер PaperFlux с транспортом Yandex Docs. Текущий путь ориентирован на IPv4/TCP; поддержка произвольного UDP-трафика и IPv6 не заявляется. Используйте клиент и сервер с совместимой реализацией PFS2.
