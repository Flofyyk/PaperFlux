# PaperFlux Server

**Русский** · [English](README.en.md) · [Android-клиент](https://github.com/Flofyyk/PaperFluxAndroid) · [Релизы](https://github.com/Flofyyk/PaperFlux/releases/latest)

Сервер VPN-туннеля PaperFlux с передачей данных через Yandex Docs и Mail.ru Документы. Принимает трафик клиента через документный транспорт и направляет его в интернет.

В [версии 0.5.13](https://github.com/Flofyyk/PaperFlux/releases/tag/v0.5.13) улучшено восстановление Mail.ru и по умолчанию отключены RACK/TLP для документных транспортов.

## Возможности

- Защищённые сессии с отдельным ключом доступа для каждого профиля.
- Два канала Yandex Docs и дополнительный резервный канал Volga.
- Автоматическое восстановление соединения и проверка доступности DNS/TCP.
- Ограниченные очереди, контроль скорости и числа активных потоков.
- Подтверждение готовности сервера перед передачей данных и окно защиты от повторов на 4096 пакетов.
- Режим `proxy` для IPv4 TCP/UDP без root и пакетный режим `raw` для Linux.
- Групповой proxy для нескольких независимых профилей в одном процессе — экспериментальный режим.

## Принцип работы

```text
Android-клиент ↔ документный транспорт ↔ PaperFlux Server ↔ интернет
```

Клиент и сервер подключаются к общим документам. Данные объединяются в батчи, сжимаются и передаются в зашифрованной сессии. На VPS сервер восстанавливает пакеты и обрабатывает исходящие соединения; ответы возвращаются по тому же пути.

Основной транспорт Yandex Docs использует сообщения курсора в канале совместного редактирования, не записывая трафик в текст документа. Volga использует текстовые операции и требует отдельного пустого документа с правом редактирования.

При потере одного документного канала оставшийся продолжает передачу. Закрытый канал восстанавливается независимо. Готовность туннеля подтверждается после авторизации, установления защищённой сессии и проверки DNS/TCP.

После перезапуска сервера Session повторно подтверждает соединение новым challenge, не ожидая истечения таймаута старой сессии. Устаревшее подтверждение не заменяет действующую сессию.

## Развёртывание

Для Linux доступны готовые бинарники `amd64` и `arm64` в [релизах](https://github.com/Flofyyk/PaperFlux/releases/latest). Выбор архитектуры по `uname -m`: `x86_64` — `amd64`, `aarch64` — `arm64`.

1. Установите бинарник на VPS.
2. Подготовьте документ и параметры профиля: ID, ключ доступа и виртуальный IP клиента.
3. Запустите сервер с `--session` и настройте systemd-сервис.
4. Добавьте соответствующий профиль в Android-клиент.

Пример запуска одного профиля:

```bash
./paperflux --exit-node --session --mode proxy \
  --transport yandex \
  --urls "https://disk.yandex.ru/i/DOCUMENT_ID" \
  --client-ip 10.10.10.2 \
  --profile-id 1 \
  --profile-token "REPLACE_WITH_RANDOM_PROFILE_KEY"
```

Замените адрес документа и ключ примера своими значениями. На клиенте и сервере должны совпадать ID, ключ, виртуальный IP и параметры транспорта.

[Полная инструкция развёртывания](docs/DEPLOYMENT.md) включает настройку пользователя, systemd и обновление сервера. Режим `raw` требует root и дополнительных настроек Linux; IPv6 не поддерживается. Legacy PFS2 несовместим с Session.

Параметры TCP recovery, буферов и входной очереди proxy описаны в [настройках транспортов](docs/TRANSPORTS.md#tcp-recovery-для-документных-каналов). Для проверки DNS/TCP зарезервирован отдельный небольшой пул соединений; заполнение обычного пула не занимает его позиции.

## Сборка

Требуется Go 1.26.4 или новее. Сборка на Linux:

```bash
git clone https://github.com/Flofyyk/PaperFlux.git
cd PaperFlux
go build -trimpath -o paperflux .
```

Для пересборки Android-ядра используется [build-android-native.ps1](scripts/build-android-native.ps1) с Android NDK.

## Безопасность

Session шифрует соединение между клиентом и VPS с использованием AES-256-GCM. Защита трафика после VPS зависит от протокола приложения, например HTTPS. Документный сервис может видеть время и объём обмена. Конфигурация профиля содержит ключ доступа и должна передаваться только доверенным получателям.
