# PaperFlux

PaperFlux — Android-клиент системного TUN-туннеля с Yandex Docs transport. В репозитории находятся серверные компоненты OpenFlux; APK собирается из отдельного проекта `openflux-android`.

## Как это работает

```text
Android TUN → native bridge → Yandex Engine.IO/WebSocket → VPS exit-node → Internet
```

Трафик передаётся совместимыми с Yandex transport сообщениями: адаптивные батчи до 32 КБ, WebSocket compression после упаковки и Base64/Socket.IO framing. DNS по умолчанию — 77.88.8.8 и 77.88.8.1.

### Шифрование и ограничения

В новой совместно обновляемой паре Android/VPS реализован PFS2: AES-256-GCM для батчей, scrypt для получения ключа аутентификации из случайного секрета профиля и X25519 для эфемерного обмена ключами. До подтверждения ключа данные не принимаются. Разные направления имеют разные ключи; номер сообщения проверяется против повторного воспроизведения. Незашифрованный старый формат не принимается. Подробности и ограничения: [PFS2](SECURITY_PFS2.md).

Это новый протокол без независимого криптографического аудита, а не заявление о готовности к публичному production. Обе стороны обновляются одновременно. Старые секреты, передававшиеся через документ открыто, необходимо перевыпустить; одного обновления бинарников для их безопасности недостаточно.

Текущая реализация — экспериментальный IPv4/TCP-туннель. UDP, IPv6 и полноценная замена WireGuard не заявляются; провайдер документа видит метаданные соединения (время, размеры и частоту сообщений), а доступ к документу позволяет остановить сессию.

## Быстрый запуск VPS

1. Соберите Linux-бинарник из корня проекта: `go build -o openflux-linux-amd64 .`.
2. Запустите exit-node с конфигурацией документа и секретом, не помещая токены в Git.
3. Для автозапуска используйте systemd и ограничьте сервис отдельным пользователем.
4. Проверяйте состояние: `systemctl status paperflux-manager` и `journalctl -u paperflux-manager -f`.

На VPS включаются только измеренные настройки TCP. BBR можно проверить сравнительным тестом; постоянный режим не должен включаться вслепую.

## APK и профиль

APK проект находится в `openflux-android`. Приложение не содержит встроенного сервера или документа: пользователь импортирует `paperflux://config?...` из буфера или добавляет профиль вручную. Профиль хранит имя, ссылку Yandex Docs, идентификатор, токен и виртуальный IP. Токены не публикуйте в issues, README и скриншотах.

```text
paperflux://config?id=<id>&name=<name>&server=<vps>&ip=10.10.10.x&doc=<yandex-doc-url>&token=<secret>
```

После импорта выберите профиль на вкладке «Профили» и только затем нажмите центральную кнопку подключения.

Для нескольких пользователей выдавайте каждому отдельный профиль/виртуальный IP и ограничивайте число соединений и полосу на exit-node. Не используйте один токен документа как публичный пароль.

## Журнал

Экран диагностики удалён. Перед CONNECTED клиент ожидает подтверждение шифрованного VPS и успешный DNS-over-TCP ответ через туннель. Фоновая проверка повторяется примерно раз в 10 секунд; потеря связи отображается с задержкой таймаута, а не мгновенно. Причины ошибок доступны в журнале. Это проверка маршрута до DNS, не гарантия доступности каждого сайта.

## Сборка

```powershell
cd paperflux-design-20260912
npm ci
npm run build
cd ..\openflux-android
.\gradlew.bat assembleDebug
```

## Интерфейс

Gradle автоматически собирает веб-интерфейс и копирует его в `assets/paperflux/index.html`. В приложении четыре вкладки: «Главная», «Профили», «Журнал», «Настройки».

Старые иллюстрации исключены из описания: они не соответствуют текущему интерфейсу. Перед публикацией нужны актуальные проверенные скриншоты.
