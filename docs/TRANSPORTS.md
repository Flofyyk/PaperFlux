# Транспорты PaperFlux

На клиенте и сервере должны совпадать ID профиля, секрет, транспорт и ресурс. Новая пара Android/Server использует шифрованную Session с batched/zstd. Старый PFS2 сохранён отдельно, без `--session`; его нельзя смешивать с Session. Бинарники обычного OpenFlux не являются взаимозаменяемыми с профилями PaperFlux.

| Значение `--transport` | Ресурс | Особенности |
| --- | --- | --- |
| `yandex` | `--urls` с одной или двумя ссылками disk.yandex.ru | Старый редактор OnlyOffice; независимые каналы в одной Session |
| `vyandex` | `--url` с одной ссылкой disk.yandex.ru | Volga; нужен отдельный пустой документ, так как транспорт изменяет его содержимое |
| `cupsonline` | `--url` со списком комнат из профиля | Числовой формат курсоров Cups; обе стороны должны быть обновлены |
| `mailru` | `--url` с публичной ссылкой cloud.mail.ru/public/… | Отдельный пустой документ; при праве редактирования отправляются периодические правки |

Для Cups сервер без списка комнат создаёт комнаты. После создания менеджер сохраняет выданный список в профиль и использует его при следующих запусках. При сетевой ошибке список не заменяется автоматически. Если все комнаты действительно закрыты, потребуется новый список на клиенте.

Mail.ru в `0.5.16` сохраняет подключение и сообщения из [OpenFlux 74cac6d](https://github.com/p1neappleXpress/OpenFlux/blob/74cac6d47bf4c27947348ee957538a2c0728a485/transport/mailru/mailru.go), дополняя их подтверждением `authChangesAck` для каждого блока истории документа. Сначала принимается Engine.IO open, затем подтверждается Socket.IO и отправляется авторизация редактора. Большие ответы редактора принимаются с верхней границей 64 МиБ; история документа не копируется в карты обработчика управления. Отказ редактора немедленно закрывает текущую сессию и запускает восстановление, а не ожидает закрытия сокета провайдером. Все записи курсоров в объединённом сообщении доставляются по порядку. При наличии `permissions.edit` отправляются периодические `saveChanges`; документ нельзя использовать для важных данных. Ссылка только для чтения не отклоняется локально, но правки по ней не отправляются. Сохранены отмена при остановке, проверка адреса редактора и защита приватных данных. Формат профилей и защищённой Session не меняется.

В Session с `--transport yandex` можно добавить резервный канал Volga через `--volga-url https://disk.yandex.ru/i/EMPTY_EDITABLE_DOCUMENT`. Это отдельный пустой редактируемый документ, не один из адресов `--urls`: передача изменяет его текст. На клиенте указывается тот же адрес в параметре `volga` полной ссылки профиля. В JSON профиля и групповом manifest поле называется `volgaUrl`. Добавление третьей обычной ссылки в `--urls` не заменяет настройку Volga.

## Проверка Яндекса

Простая proof-of-work проверка обрабатывается автоматически с ограничением времени и числа запросов. SmartCaptcha или необходимость входа требуют участия пользователя. Повторные попытки в этом случае замедляются; Stop отменяет HTTP-запросы и вычисления.

В Android при необходимости подтверждения открывается отдельное окно WebView. Cookies собираются с начальной страницы и конечного адреса после перенаправления. Запросы телефона и сервера не перезаписывают уже открытую проверку. Переход на Session не отменяет проверки доступа Яндекса. Cookies остаются в приватном хранилище, не входят в QR-код и не передаются боту.

Окно проверки и служебный прокси поддерживают доверенные региональные домены `yandex.ru`, `yandex.com`, `yandex.by`, `yandex.kz`, `yandex.uz` и `yandex.com.tr`. Cookies конечной страницы имеют приоритет над одноимёнными cookies корневого адреса. При передаче используется домен проверки; региональные cookies сохраняются отдельно. Это не расширяет допустимые ссылки при импорте профиля.

Новый результат проверки дополняет сохранённые cookies, не стирая прежнюю авторизацию. Фоновый ответ VPS не заменяет уже имеющиеся cookies телефона; cookies учётной записи не включаются в такой ответ. Получение cookies само по себе не завершает запрос проверки: документный канал должен действительно восстановиться.

Внутренние запросы разных документов и сторон ожидают в ограниченной очереди. Ответ связан с идентификатором запроса и текущей попыткой подключения. Отмена откладывает повторный запрос на 10 минут. Во время ожидания пользователя сетевой таймаут приостановлен; ручное отключение останавливает подключение. Общий предел ожидания — 30 минут.

В старом режиме PFS2 сервер может прочитать cookies из приватного файла, путь к которому задан переменной `PAPERFLUX_YANDEX_COOKIES`. JSON содержит объекты `disk.yandex.ru` и `docs.yandex.ru`, внутри каждого — пары имя/значение cookie. Session использует отдельное хранилище `PAPERFLUX_SESSION_COOKIES` и обновляет его через защищённый обмен приложения и сервера. Не смешивайте форматы этих файлов. Ограничьте права владельцем сервиса; не включайте cookies в профиль, логи или репозиторий. Cookies с другого IP могут не пройти проверку.

### Серверная проверка при недоступных документах

Session может использовать отдельный служебный канал: на сервере `--auth-service 0.0.0.0:PORT`, на клиенте `--auth-service SERVER:PORT`. Менеджер с `PAPERFLUX_SESSION=1` назначает порт `PAPERFLUX_AUTH_PORT_BASE + ID` (база по умолчанию 24000). Android вычисляет порт из сервера и ID профиля. Обновлять нужно обе стороны.

Канал требует секрет профиля, взаимную проверку HMAC и шифрование Session. Он передаёт только управление и HTTPS-проверку на разрешённых доменах Яндекса. DNS-адреса проверяются и закрепляются при соединении; приватные и служебные сети запрещены. Потоки, очередь и время ожидания ограничены. При отсутствии прокси серверная страница не открывается напрямую с телефона. Служебное соединение не переносит обычный VPN-трафик и не считается готовым VPN-каналом.

Откройте только назначенные порты своим правилом firewall; не включайте и не заменяйте весь firewall без проверки действующей настройки. Файл `PAPERFLUX_SESSION_COOKIES` должен быть доступен только владельцу сервиса. Успех передачи cookies не равен успеху туннеля: статус подключения требует готового документного канала и DNS/TCP-проверки.

## Источники изменений

Перенесены и адаптированы части [OpenFlux](https://github.com/p1neappleXpress/OpenFlux), GPL-3.0: Session/IPC, batched/zstd, CAPTCHA, ограничение DialTCP и новый протокол Cups. Поведение проверки сопоставлено с [OpenFlux-Android](https://github.com/damnurmum/OpenFlux-Android). Регрессия Engine.IO из [issue 106](https://github.com/p1neappleXpress/OpenFlux/issues/106) исправлена в Session-транспорте: polling → sid → WebSocket → 2probe/3probe/5, cookies polling-ответа и новый ID участника на каждую попытку. Это устраняет конкретную ошибку подключения, но не гарантирует отсутствие последующих закрытий со стороны сервиса.

Клиент ждёт подтверждения `Ready=1` от exit перед передачей DATA, включая замену peer после перезапуска. Координация поколений авторизации Volga адаптирована из [GEFSED/OpenFlux](https://github.com/GEFSED/OpenFlux/tree/codex/volga-http-401-reauth): HTTP и WebSocket разделяют одну попытку обновления, а неуспешный refresh сохраняет последнюю рабочую авторизацию.

## TCP recovery для документных каналов

Начиная с `0.5.13`, режим `auto` (в том числе отсутствие параметра) выбирает `classic` для Яндекса, Volga и Mail.ru. Он отключает RACK/TLP в используемом стеке gVisor, сохраняя восстановление по ACK/SACK и RTO. Другие транспорты сохраняют штатный режим. Явные `--tcp-recovery classic` или `PAPERFLUX_TCP_RECOVERY=classic` закрепляют отключение; `--tcp-recovery rack` / `default` возвращают штатный режим. Настройка действует на процесс, не меняет wire-протокол и не настраивает TCP удалённого сайта или ядра Linux. CLI разрешает `classic` только для документных транспортов. Групповой документный proxy использует тот же режим.

Локальный тест задержки ACK запускается командой `PAPERFLUX_TEST_TCP_STALL=1 go test ./tunnel -run TestTCPRecoveryACKStallAB -count=3 -v`. Он не обращается к внешним сервисам и не заменяет замер реального документного канала.

### Настройка TCP-буферов

`PAPERFLUX_TCP_BUFFER_KIB` задаёт исходный размер отправки и приёма, `PAPERFLUX_TCP_BUFFER_MAX_KIB` — верхнюю границу каждой стороны. Допустимы 256–2048 КиБ. Без переменных остаются 256 КиБ / 1 МиБ. Эти параметры действуют только на gVisor данного процесса; системные буферы Linux не меняются. При увеличении учитывайте оба направления, число активных TCP-потоков и лимит памяти процесса.

`PAPERFLUX_TCP_BUFFER_PRESET=upstream` включает точные значения текущего OpenFlux: минимум 4 МиБ, по умолчанию 16 МиБ, максимум 64 МиБ для каждого направления TCP. Этот явный режим имеет приоритет над двумя переменными размеров выше. Его нельзя включать массово без отдельного бюджета памяти: большие окна не доказывают увеличение скорости и могут исчерпать память при множестве активных соединений. Без preset общие узлы сохраняют прежние ограниченные значения.

Android `0.4.22` запускает Яндекс, Volga и Mail.ru с `classic` recovery. Для Mail.ru также включён preset `upstream` (4 / 16 / 64 МиБ в каждом направлении); до `0.4.22-rc.2` использовался 1 МиБ. Размеры буферов других транспортов не меняются. Изменение не требует другого формата пакетов; соответствующее выходное ядро должно поддерживать выбранные параметры и иметь достаточный бюджет памяти.

Согласование Session сохраняет установленного peer, пока новый участник не ответит на свежий challenge. Запустить замену может только discovery с нулевым адресатом; адресованный Hello принимается для замены лишь при точном совпадении с уже выданным challenge. Это правило соответствует upstream и предотвращает повторный запуск замены из встречных адресованных Hello. `peer_replaced` содержит только номер поколения и роль процесса, без ключей и идентификаторов участников.

Proxy-выход резервирует четыре отдельные TCP-позиции к существующим DNS/TCP-проверочным адресам `77.88.8.8:53` и `77.88.8.1:53`: заполнение обычного пула не должно само по себе вызывать ошибочную потерю туннеля. Для ограниченной входной очереди доступны `PAPERFLUX_PROXY_QUEUE_PACKETS` (128–1024) и `PAPERFLUX_PROXY_QUEUE_KIB` (256–2048). По умолчанию сохраняются 128 пакетов / 256 КиБ. Счётчик `flow_rejected` показывает отказы из-за заполнения пула, отдельно от очереди транспорта.
