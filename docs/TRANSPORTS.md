# Транспорты PaperFlux

На клиенте и сервере должны совпадать ID профиля, секрет, транспорт и ресурс. Новая пара Android/Server использует шифрованную Session с batched/zstd. Старый PFS2 сохранён отдельно, без `--session`; его нельзя смешивать с Session. Бинарники обычного OpenFlux не являются взаимозаменяемыми с профилями PaperFlux.

| Значение `--transport` | Ресурс | Особенности |
| --- | --- | --- |
| `yandex` | `--urls` с одной или двумя ссылками disk.yandex.ru | Старый редактор OnlyOffice; независимые каналы в одной Session |
| `vyandex` | `--url` с одной ссылкой disk.yandex.ru | Volga; нужен отдельный пустой документ, так как транспорт изменяет его содержимое |
| `cupsonline` | `--url` со списком комнат из профиля | Числовой формат курсоров Cups; обе стороны должны быть обновлены |
| `mailru` | `--url` с публичной ссылкой cloud.mail.ru/public/… | Документ должен быть доступен на редактирование |

Для Cups сервер без списка комнат создаёт комнаты. После создания менеджер сохраняет выданный список в профиль и использует его при следующих запусках. При сетевой ошибке список не заменяется автоматически. Если все комнаты действительно закрыты, потребуется новый список на клиенте.

## Проверка Яндекса

Простая proof-of-work проверка обрабатывается автоматически с ограничением времени и числа запросов. SmartCaptcha или необходимость входа требуют участия пользователя. Повторные попытки в этом случае замедляются; Stop отменяет HTTP-запросы и вычисления.

В Android 0.4.14 ручные кнопки проверки убраны из интерфейса и уведомления. Внутренний обмен cookies сохранён для совместимости, но при новой SmartCaptcha подключение может потребовать решения проверки вне обычного интерфейса приложения. Переход на Session не отменяет проверки доступа Яндекса. Cookies остаются в приватном хранилище, не входят в QR-код и не передаются боту.

Внутренние запросы разных документов и сторон ожидают в ограниченной очереди. Ответ связан с идентификатором запроса и текущей попыткой подключения. Отмена откладывает повторный запрос на 10 минут. Во время ожидания пользователя сетевой таймаут приостановлен; ручное отключение останавливает подключение. Общий предел ожидания — 30 минут.

В старом режиме PFS2 сервер может прочитать cookies из приватного файла, путь к которому задан переменной `PAPERFLUX_YANDEX_COOKIES`. JSON содержит объекты `disk.yandex.ru` и `docs.yandex.ru`, внутри каждого — пары имя/значение cookie. Session использует отдельное хранилище `PAPERFLUX_SESSION_COOKIES` и обновляет его через защищённый обмен приложения и сервера. Не смешивайте форматы этих файлов. Ограничьте права владельцем сервиса; не включайте cookies в профиль, логи или репозиторий. Cookies с другого IP могут не пройти проверку.

### Серверная проверка при недоступных документах

Session может использовать отдельный служебный канал: на сервере `--auth-service 0.0.0.0:PORT`, на клиенте `--auth-service SERVER:PORT`. Менеджер с `PAPERFLUX_SESSION=1` назначает порт `PAPERFLUX_AUTH_PORT_BASE + ID` (база по умолчанию 24000). Android вычисляет порт из сервера и ID профиля. Обновлять нужно обе стороны.

Канал требует секрет профиля, взаимную проверку HMAC и шифрование Session. Он передаёт только управление и HTTPS-проверку на разрешённых доменах Яндекса. DNS-адреса проверяются и закрепляются при соединении; приватные и служебные сети запрещены. Потоки, очередь и время ожидания ограничены. При отсутствии прокси серверная страница не открывается напрямую с телефона. Служебное соединение не переносит обычный VPN-трафик и не считается готовым VPN-каналом.

Откройте только назначенные порты своим правилом firewall; не включайте и не заменяйте весь firewall без проверки действующей настройки. Файл `PAPERFLUX_SESSION_COOKIES` должен быть доступен только владельцу сервиса. Успех передачи cookies не равен успеху туннеля: статус подключения требует готового документного канала и DNS/TCP-проверки.

## Источники изменений

Перенесены и адаптированы части [OpenFlux](https://github.com/p1neappleXpress/OpenFlux), GPL-3.0: Session/IPC, batched/zstd, CAPTCHA, ограничение DialTCP и новый протокол Cups. Поведение проверки сопоставлено с [OpenFlux-Android](https://github.com/damnurmum/OpenFlux-Android). Регрессия Engine.IO из [issue 106](https://github.com/p1neappleXpress/OpenFlux/issues/106) исправлена в Session-транспорте: polling → sid → WebSocket → 2probe/3probe/5, cookies polling-ответа и новый ID участника на каждую попытку. Это устраняет конкретную ошибку подключения, но не гарантирует отсутствие последующих закрытий со стороны сервиса.
