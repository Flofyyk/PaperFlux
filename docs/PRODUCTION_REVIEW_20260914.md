# Ревью PaperFlux — 14 сентября 2026

Результат: публичный production-релиз пока не готов. Проверены локальный Go core, Android service/bridge, React UI, Python manager/bot и доступность работающих сервисов VPS. Это статический review с проверками сборки, не нагрузочный или криптографический аудит.

## Блокеры

1. **P0: токен профиля не проверяется в локальном Yandex transport.** `transport/yandex/yandex.go`, `handleMessage`: сообщение `paperfluxIdentity` только логируется и отбрасывается. Приём payload не привязан к успешной проверке личности. Знание документа нельзя считать достаточной авторизацией. Нужны проверка допуска до данных, отзыв доступа и отрицательные тесты.
2. **P1: профили переключаются неполностью.** React `App.tsx` сохраняет только id/name/server/documentUrl, а `onSelect` вызывает `setDocumentUrl`. Native profile_id/token/client_ip остаются от последнего импорта. Удаление активного профиля вызывает `clearConfig`, но визуально выбирает следующий, не применяя его секреты. Нужен единый native store полных профилей и атомарный выбор.
3. **P1: нет доказательства соответствия рабочего бинарника исходникам.** VPS `/opt/openflux-test/openflux-multuser-linux-amd64` SHA-256: `88be63c4d16e1ce21b3579b72036f438ef884e08caa91f0162389aab14ce8dce`. Наличие бинарника и работа сайта не доказывают соответствие текущей dirty-копии репозитория. Перед релизом нужны фиксированная ревизия, сборка core для телефона/VPS и проверка пары на стенде.
4. **P1: состояние CONNECTED переоценивает готовность.** Android выставляет его после авторизации документа и передачи FD; независимой проверки DNS/TCP через exit нет. Watchdog проверяет внешний адрес через базовую сеть, что не доказывает исправность туннеля. Отмена запуска также конкурирует с циклом ожидания авторизации.
5. **P1: секреты/модель защиты.** В локальном Yandex transport нет AES-GCM/scrypt. Токен профиля хранится в обычных SharedPreferences и передаётся через документ. WebView с JavaScript bridge не ограничивает переходы явным allowlist. Нужны защищённое хранение, политика навигации и отдельная модель авторизации/шифрования.
6. **P2: эксплуатационные лимиты неполные.** Bot отображает квоту, manager не останавливает трафик по этой квоте. CPU nice/RLIMIT_AS не обеспечивают справедливую полосу. RLIMIT_AS ограничивает виртуальное адресное пространство Go; необходим отдельный тест под нагрузкой.
7. **P2: потери/нагрузка.** `drainOutbound` теряет пакет при ошибке Send; `getLocalIP` создаёт UDP-сокет в горячем пути rawsocket; нет подтверждённой нагрузочной проверки длинных сессий. Эти изменения требуют отдельного измерения, не механической очистки.

## Исправлено при ревью

- Устранена причина оставшейся диагностики: обновлялся `assets/index.html`, но WebView читает `assets/paperflux/index.html`. Gradle теперь собирает UI и копирует его в используемый путь.
- Неиспользуемая копия assets/index.html перенесена в backup. Удалены три неиспользуемых drawable (включая колбу); копии сохранены.
- Убран повтор старого last_event в onPageFinished; используется снимок getState. Журнал React очищается перед ручным подключением.
- Исправлена ошибка строгой типизации TypeScript; typecheck включён в npm build.
- В rawsocket освобождается временный gVisor View; до освобождения создаётся собственная копия пакета.
- Manager читает только хвост лог-файла до 12 КБ вместо загрузки всего файла в память.
- Документация больше не заявляет неподтверждённое AES-GCM и удалённую диагностику. Устаревшие скриншоты убраны из текста.

Затем настроить постоянную release-подпись APK (сейчас debug/preview).

## Стабильность после ревью

- WebSocket-сессия теперь имеет одного владельца: перед заменой старая закрывается, а её поздние ошибки не могут изменить состояние новой сессии. Reconnect объединяется через один pending-флаг и использует экспоненциальную задержку с jitter.
- Пустой editor cursor отправляется только после простоя; Engine.IO ping/pong остаётся штатным. Bootstrap использует отдельные TCP/TLS/HTTP таймауты и до трёх повторов для временных сетевых ошибок.
- DNS/TCP probe выполняется сразу после старта и далее раз в 45 секунд. Срыв считается потерей после трёх подряд ошибок; повторные успешные проверки не создают новые CONNECTED-события.
- TUN2Socks запускается после готовности локального SOCKS5 listener. В gVisor освобождаются временные View; NAT сохраняет исходный IP клиента до SNAT.
- Проверены `go test ./...`, `go vet ./...`, Android assemble/lint и instrumentation `ProfileStoreTest`. Обновлённый APK установлен на подключённое устройство, серверный worker перезапущен на VPS.

Это устраняет выявленные программные гонки и ложные реконнекты, но не может запретить самому Yandex балансеру закрыть соединение. Длительный LTE/Wi-Fi soak-тест и release-подпись APK остаются обязательными перед публичной раздачей.
