# Несколько пользователей и серверов

## Изоляция пользователей

Каждому профилю нужны собственный секрет, виртуальный IP и отдельные документы. Один документ нельзя одновременно назначать разным профилям или exit-узлам, даже с разными вариантами транспорта Яндекса.

Обычный exit-worker обслуживает один профиль. В Linux raw-режиме NAT резервирует уникальные внешние TCP/UDP-порты обычными сокетами ядра: они не пересекаются с другими workers и исходящими соединениями VPS. Ответы возвращаются только соответствующему виртуальному адресу и порту.

Переменные окружения native-worker:

| Параметр | Значение |
| --- | --- |
| `PAPERFLUX_MAX_FLOWS` | Максимум активных потоков: 16–4096, по умолчанию 256 |
| `PAPERFLUX_MAX_MBIT` | Потолок отдельно на загрузку и отдачу в десятичных Мбит/с; `0` — без ограничения |

Ограничение скорости действует на IP-пакеты, не на управляющие сообщения Session. Это потолок, а не гарантия фактической скорости: CPU, полоса VPS и ограничения документного сервиса остаются общими.

Ограничивайте память, число задач и CPU через systemd/cgroup v2. Вместимость определяйте совместной нагрузкой и метриками; увеличение `LimitNOFILE` или swap само по себе не делает VPS пригодным для сотен пользователей.

## Групповой proxy

Экспериментальный режим объединяет несколько независимых профилей в одном процессе. У каждого остаются собственные Session, документы, сетевой стек и лимиты. Ошибка или OOM общего процесса затронет группу целиком.

[Контракт manifest, статистика и ограничения](EXPERIMENTAL_GROUPS.md). Режим включается явно через `--exit-profiles`; он не активируется автоматически при обновлении сервера. Управляющий сервис должен своевременно обновлять приватный manifest и подтверждать учёт завершённых эпох. Публичное серверное ядро не включает Telegram-бота или готовую систему управления VPS.

## Распределение между VPS

Каждый узел самостоятельно принимает данные через назначенные ему документы и выпускает трафик в интернет. При создании профиля управляющая система выбирает готовый VPS и выдаёт его адрес, ключ и документы. Существующие соединения не переезжают автоматически при изменении нагрузки.

Нельзя перенести этот путь обычным DNAT служебного порта: доступ к документам и защищённая Session должны работать на выбранном exit-узле. Документы одного профиля нельзя параллельно запускать на разных VPS.

Android 0.4.16 поддерживает импорт набора `paperflux://pool?data=…` из 2–8 отдельных полных конфигураций уже настроенных серверов. Это статический резерв, не автообновляемая подписка и не автоустановка. При смене VPS возможны пауза и смена внешнего IP; открытые TCP-соединения устанавливаются заново.
